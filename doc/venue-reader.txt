Venue Reader                                                  *venue-reader*

Venue Reader is an LSP server for FIX logs. This optional plugin adapts its
features to Neovim and adds server installation, summary rendering and small
command helpers. Protocol analysis and dictionary data belong to the server.
Requires Neovim 0.12 or later.

The server also works with Neovim's native LSP client without this plugin.
Hover, diagnostics, code actions, document links, selection ranges and document
symbols use Neovim's standard interfaces. The plugin does not replace them.

First use                                                *venue-reader-usage*

Install with |venue-reader-setup|, then open a *.fix file or use: >vim
    set ft=fix
<
LSP attachment requires a normal buffer with an explicit name. A named buffer
need not exist on disk. To name one without saving: >vim
    file /path/log.fix
<
:saveas also works. Renaming closes the old server document before opening the
new one. By default the project root is the nearest parent containing
.venue-reader.toml, otherwise the file's directory. Native root_dir can supply
a different rule; see |venue-reader-native-config|. Buffers in the same managed session share a
client. Optional syntax can work in unnamed FIX buffers too.

Use Neovim's native LSP interfaces to inspect fields and messages. For example:
>lua
    vim.lsp.buf.hover()
    vim.lsp.buf.code_action()
    vim.lsp.buf.document_symbol()
    vim.diagnostic.open_float()
<
The outline provides message navigation. Group detail in that outline is a
server setting. There are no plugin key bindings by default; optional yank and
syntax mappings are in |venue-reader-mappings| and |venue-reader-navigation|.

Front summaries appear before raw messages by default. Change placement with:
>vim
    VenueReader summary above
    VenueReader summary hidden
    VenueReader summary codelens
    VenueReader summary off
<
These are the modes in |venue-reader-modes|. Decoded text can be copied with
|venue-reader-yank| and pasted normally, including into a new buffer.

Inspect the current session and requirements with: >vim
    VenueReader status
    checkhealth venue-reader
<
Other clients' diagnostics and providers are preserved. Native Neovim owns LSP
requests, refreshes and lifecycle; the plugin does not scan FIX in Lua or recover
results omitted by server limits.

Troubleshooting                                *venue-reader-troubleshooting*

Another FIX plugin loaded first ~
fix.nvim and venue-reader.nvim share a load marker. The first plugin to load
wins; the second warns once and skips initialization. A blocked setup() does
nothing. Disable the unwanted plugin in your plugin manager and restart Nvim.
Runtimepath entries remain, so installed Tree-sitter queries can still be found.
The guard does not detect other FIX plugins or independently configured clients.

No LSP attachment ~
Check filetype=fix, normal buffer type, an explicit buffer name and native LSP
enablement. Run :VenueReader status and :checkhealth venue-reader. A buffer can
have a name without a saved file. :lsp enable venue_reader enables attachment;
:lsp disable venue_reader prevents future automatic attachment.

Server installation failed ~
Check acquisition state, platform and required tools in |venue-reader-server|.
Fix the cause and use :VenueReader install server. A compatible explicit binary
with auto_install=false is suitable for offline use. An invalid explicit command
is an error; it is not silently replaced with another executable.

No summaries or field hints ~
Check the mode, native inlay/CodeLens gates, effective channel/master switches
and server caps in |venue-reader-summary-limits|. Correct project/modeline
conflicts and select the desired mode again. A document over the inlay range
cap can have no inlay summaries or field hints. Modes do not fall back or raise
limits automatically.

Configuration not ready ~
Initial native requests can report that document configuration is not ready.
Native server refresh supplies current annotations. Explicit commands report
the error without polling; retry after configuration completes.

Summaries disappear while appending ~
Edits hide old custom summaries until a current response arrives. Appending to
a log can briefly hide them on each change.

No optional syntax or selection ~
Inspect grammar state, toolchain and manager load order. Fix the cause and run
:VenueReader install grammar. Incompatible parsers or incomplete manager
installations can need manual repair and a Neovim restart. Retry does not force
an overwrite. Invalid textobject queries do not disable base highlighting.
See |venue-reader-treesitter| and |venue-reader-textobjects|.

No clipboard output ~
Inspect Neovim's clipboard provider. Explicit register writes can partially
succeed before a provider failure, and some providers only emit warnings.
See |venue-reader-registers| for destination selection.
