*venue-reader-setup.txt*  Installation and configuration

Setup                                                   *venue-reader-setup*

Index: |venue-reader|    Commands: |venue-reader-commands|
Wiki: https://github.com/sergluka/venue-reader.nvim/wiki/Installation

Choose one package manager. Requires Neovim 0.12 or later.

==============================================================================
LazyVim                                            *venue-reader-lazyvim*

Create lua/plugins/venue-reader.lua in your Neovim configuration directory:
>lua
    -- lua/plugins/venue-reader.lua
    return {
      {
        "sergluka/venue-reader.nvim",
        dependencies = { -- optional
          { "folke/snacks.nvim", opts = { picker = { enabled = true } } },
          { "nvim-treesitter/nvim-treesitter", branch = "main" },
          { "nvim-treesitter/nvim-treesitter-textobjects", branch = "main" },
        },
        opts = {}, -- adapter options
        config = function(_, opts)
          vim.lsp.config("venue-reader", { settings = { fix = {} } })
          require("venue-reader").setup(opts)
        end,
      },
    }
<
The config function registers native settings before setup. The Tree-sitter
dependencies use main APIs; ensure your LazyVim configuration uses those APIs.
The inner spec also works in a standalone lazy.nvim configuration. The manager
is only needed for parser installation; textobjects is only needed for syntax
selection/navigation. No other Neovim plugin is required for LSP features.
The progressive |venue-reader-symbols| picker needs snacks.nvim; native
document-symbol commands do not. Remove optional dependencies you do not need.
To disable the picker command, set opts.symbols.enabled = false.

==============================================================================
Native packages                                     *venue-reader-pack*

Add this to init.lua for Neovim's built-in package manager:
>lua
    -- init.lua
    vim.pack.add({
      {
        src = "https://github.com/sergluka/venue-reader.nvim",
      },
    })
    require("venue-reader").setup()
<
Update the package with: >vim
    lua vim.pack.update({ "venue-reader.nvim" })
<
A package loaded by another manager also needs the same setup() call.
Server discovery starts when a named FIX buffer is opened.
See |venue-reader-usage|.

==============================================================================
Configuration                                      *venue-reader-options*

Upgrading from venue_reader ~
Use venue-reader in vim.lsp.config(), vim.lsp.enable(), vim.lsp.get_clients()
name filters and :lsp commands. Rename any lsp/venue_reader.lua or
after/lsp/venue_reader.lua file to venue-reader.lua in the same directory.

Defaults: >lua
    require("venue-reader").setup({
      server = { auto_install = true },
      summary = { mode = "front", semantic_highlighting = true },
      commands = { timeout_ms = 5000 },
      symbols = { enabled = true, timeout_ms = 30000 },
      treesitter = { enabled = true, auto_install = true },
    })
<
server.auto_install ~
Allow asynchronous verified server installation when no compatible binary is
available. See |venue-reader-server|. An explicit retry is available through
:VenueReader install server.

server.cmd ~
Optional argv list without shell parsing. The executable must support --version.
For an existing binary or offline use, with optional syntax disabled:
>lua
    require("venue-reader").setup({
      server = {
        cmd = { "/absolute/path/to/venue-reader", "--stdio" },
        auto_install = false,
      },
      treesitter = { enabled = false },
    })
<
Omit treesitter.enabled=false to allow compatible parser reuse and automatic
grammar installation when the optional manager is available. LSP does not wait
for grammar installation.

summary.mode / summary.semantic_highlighting ~
Modes are front (default), above, hidden, codelens and off. Semantic summary
colors default to true; false uses only VenueReaderSummary. Set that base group
to supply a background or uniform styling. Source semantic highlighting is
independent. Native CodeLens uses LspCodeLens.
See |venue-reader-modes| and |venue-reader-styling|.

commands.timeout_ms ~
Finite positive integer; default 5000. The deadline starts when the operation
is created and covers root resolution, discovery/installation, bootstrap and
requests. Time spent choosing a dictionary is excluded. Timeouts cancel native
outstanding requests; late root resolution cannot start a client solely for an
expired command, and late answers do not write registers or previews.

symbols.enabled ~
Boolean; default true. Set false to disable the optional Snacks symbol picker
and hide symbols from :VenueReader completion. Setup and native LSP features
do not load or require Snacks. Calling a disabled picker reports an error.

symbols.timeout_ms ~
Finite non-negative integer; default 30000. Cancel document symbols after this
many milliseconds without a result, owned progress notification or response.
Zero disables the inactivity deadline. Each symbols(opts) call may override it.
This deadline is independent of commands.timeout_ms.

Native server settings ~
Register server settings with vim.lsp.config, separately from adapter options:
>lua
    vim.lsp.config("venue-reader", {
      settings = { fix = { hover = { enabled = true } } },
    })
    require("venue-reader").setup()
<
Project/modeline settings keep higher priority. Empty settings.fix is sent as a
JSON object. Native settings may be registered before or after setup, but must
precede client creation. Later registration affects future clients; use
:VenueReader restart to apply it. Repeated setup updates adapter options without
restoring the client's full settings table.

For a live change, mutate the existing settings table and notify the server:
>lua
    for _, client in ipairs(vim.lsp.get_clients({ name = "venue-reader" })) do
      client.settings.fix.hover = { enabled = false }
      client:notify("workspace/didChangeConfiguration", { settings = client.settings })
    end
<
This changes running clients only. Register the same setting with vim.lsp.config
if it should survive restart. Preserve the three managed summary keys below.

For example, native field labels can be enabled with the settings shown in
|venue-reader-field-hints|. Generic server configuration belongs to the server
reference rather than a second plugin-specific schema:
https://github.com/sergluka/venue-reader/wiki/Configuration
https://github.com/sergluka/venue-reader/wiki/Configuration-Reference

Mode selection changes only fix.messageSummary.channels.inlayHints, codeLens
and fix.messageSummary.semanticTokens in client settings. Registered native
settings stay unchanged. The mode writes these keys at each client start and each
mode change, replacing values from vim.lsp.config or live client edits.
Project/modeline conflicts are reported in status/health with
their sources; they are not overridden. See |venue-reader-summary-gates|.

treesitter.enabled / treesitter.auto_install ~
Optional syntax defaults to enabled with automatic installation allowed.
enabled can be a boolean or an enabled(bufnr) predicate. A buffer opt-out and
large-file policy are described in |venue-reader-treesitter-options|.

==============================================================================
Native overrides                                  *venue-reader-native-config*

Register native cmd, root_dir, callbacks and handlers before setup:
>lua
    vim.lsp.config("venue-reader", {
      cmd = { "/absolute/path/to/venue-reader", "--stdio" },
      root_dir = function(buffer, on_dir)
        local directory = vim.fs.root(buffer, ".git")
        if directory then
          on_dir(directory)
        end
      end,
    })
    require("venue-reader").setup()
<
Native cmd may be an argv list or transport function. It takes precedence over
server options and bypasses discovery/installation. Its server must report a
compatible version at initialize; missing, malformed or incompatible versions
stop that client. Native commands are not probed with --version.

The adapter preserves capabilities, unrelated handlers and on_attach. It runs
user before_init before preparing settings, and user on_init before reconciling
managed summary keys. Exit cleanup and user on_exit each run once. Repeated setup
does not stack callback wrappers. workspace/configuration and
textDocument/inlayHint are required adapter handlers and cannot be replaced.
Structural replacement after setup is unsupported.

Without a native root override, the default is the nearest .venue-reader.toml
directory, otherwise the file's directory (cwd for a command-only session).
This root function takes precedence over root_markers; supply root_dir for a
different rule. A custom resolver that never calls on_dir prevents attachment;
command-only operations report a timeout after commands.timeout_ms.

Status/health identifies native transports as externally configured, reports
their argv or a function-transport label, and shows the initialized server
version. It does not invent an executable path for a function transport.

==============================================================================
Server discovery                                      *venue-reader-server*

Discovery reuses a compatible explicit command, PATH executable or managed
installation, in that order. Compatible stable patch releases in the same
major/minor series as the pinned release are accepted. An invalid explicit
command fails rather than selecting another executable.

If no binary is found and auto_install is true, the pinned release installs
asynchronously under stdpath("data")/venue-reader/. The adapter verifies SHA-256
before extraction. Compatible installations are reused without automatic
upgrades, PATH changes or replacement of external installations.

Automatic installation tools ~

    Linux       curl, tar, sha256sum
    macOS       curl, tar, shasum
    Windows     curl.exe, tar.exe, certutil.exe

Missing tools or unsupported targets report a manual installation path.
Linux automatic artifacts require x86_64/glibc >=2.35. The manifest also lists
macOS x86_64/aarch64 and Windows x86_64 artifacts.

Pinned release metadata:
https://github.com/sergluka/venue-reader.nvim/blob/master/lua/venue-reader/release.json

Use :VenueReader status for session/binary/version/acquisition/failure state.
Use :checkhealth venue-reader for requirements and current global state.
After fixing an acquisition failure, retry explicitly: >vim
    VenueReader install server
<
Parser acquisition is separate and optional: |venue-reader-treesitter|.
