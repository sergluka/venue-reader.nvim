*venue-reader-commands.txt*  Commands, Lua helpers and decoded yank

Commands                              *:VenueReader* *venue-reader-commands*

Index: |venue-reader|    Configuration: |venue-reader-options|
Wiki: https://github.com/sergluka/venue-reader.nvim/wiki/Commands

:VenueReader start              Native :lsp enable venue_reader.
:VenueReader stop               Native :lsp stop venue_reader.
:VenueReader restart            Resolve executable, then native restart/enable.
:VenueReader status             Show session/server/annotation/grammar state.
:VenueReader install server     Explicit server discovery/installation retry.
:VenueReader install grammar    Explicit optional parser acquisition retry.
:VenueReader summary {mode}     Select front, above, codelens or off.
:VenueReader yank [register]    Decode the cursor field to a text register.
:[range]VenueReader yank [reg]  Decode an inclusive line range.
:VenueReader dictionary [name]  Choose or select a server dictionary.
:VenueReader settings           Preview committed settings/sources/warnings.
:VenueReader tag {number} [val] Preview a tag/value reference.
:checkhealth venue-reader       Inspect requirements/current global state.

Only yank accepts an Ex range. Tag numbers are positive decimal u32 integers;
optional values remain strings. Ex arguments follow normal space escaping.

==============================================================================
Lifecycle                                             *venue-reader-lifecycle*

Helpers use native scope: all clients named venue_reader, including different
roots. Native restart preserves attached buffers. Stop terminates current
clients; :lsp disable venue_reader prevents future automatic attachment.
:lsp enable venue_reader resumes attachment.

After a crash, native Neovim reports the exit; enable attaches eligible buffers
again. There is no separate plugin suppression or automatic recovery loop.
Restart resolves the executable, then delegates to native restart, or enables
when no client is running. Unattached command sessions use the same lifecycle.

==============================================================================
Server commands                                  *venue-reader-server-commands*

The pinned release supplies structured fix.decode results and
fix.listDictionaries. Automatic installation supplies a supporting release.
Missing commands or unsupported results are errors; the adapter does not retry
through a different interface.

Examples: >vim
    VenueReader dictionary
    VenueReader dictionary FIX.4.4
    VenueReader settings
    VenueReader tag 35
    VenueReader tag 54 1
<
The dictionary chooser uses server-supplied names and labels in vim.ui.select.
A chooser submits the selected name against the current server registry, which
can change while the UI is open. Selection is session-wide; project/modeline
overrides retain priority.

Settings opens a native floating preview of the committed effective settings,
sources and warnings. It is a one-shot snapshot, not a continuously updating
inspector. Tag opens a native Markdown reference for MsgType(35), or for
Side(54) = 1 in the second tag example.

Yank/settings require a named FIX buffer, an attached native client and ready
server configuration. Tag/dictionary also work without a FIX document. They
reuse the current owned client or a session matching cwd's nearest
.venue-reader.toml root, otherwise cwd. A new session starts unattached through
native LSP and can be reused by later FIX buffers. These commands do not change
an unrelated buffer's filetype.

Configuration-not-ready errors are reported without polling. Invoke the command
again after configuration completes. Command deadlines are described in
|venue-reader-options|.

==============================================================================
Lua helpers                                                *venue-reader-lua*

Use require("venue-reader") for the public module:

setup(opts)                    Configure and enable the adapter.
start(), stop(), restart()     Lifecycle counterparts of the commands above.
status([bufnr])                Return session/acquisition/annotations/treesitter.
install([target])              target is "server" (default) or "grammar".
summary(mode)                  Select one of the four summary modes.
yank([opts])                   Decode cursor, line or live Visual selection.
operator()                     Expression mapping for decoded g@ operator.
dictionary([name])             Choose or select the dictionary.
settings()                     Preview current committed settings.
tag(number[, value])           Preview tag/value reference.
textobject(kind)               Select tag/value/field/message/comment via syntax.

Examples: >lua
    local venue = require("venue-reader")
    venue.yank()
    venue.dictionary()
    venue.settings()
    venue.tag(54, "1")
<
textobject() needs the optional engine in |venue-reader-textobjects|.

==============================================================================
Decoded yank                                               *venue-reader-yank*

Decode the cursor field, or an inclusive line range: >vim
    VenueReader yank
    10,20VenueReader yank a
<
The equivalent Lua range is: >lua
    require("venue-reader").yank({
      mode = "line", first = 10, last = 20, register = "a",
    })
<
yank() defaults to mode="cursor". mode="line" uses inclusive one-based line
bounds; omitted bounds use the cursor line. mode="visual" needs a live Visual
selection. Use |venue-reader-mappings| for native char/line/block motions.

In Normal mode the Yank mapping uses a native g@ operator: motions, text
objects, counts and repeat use Neovim. In Visual mode it captures characterwise,
linewise or blockwise geometry before leaving Visual mode. The server decodes
fields intersecting the selection. Source text, cursor and view remain intact.

Block output preserves every source row, including empty rows, and uses decoded
text's native register width. Virtual padding adds no source bytes. Server
limits apply to the entire selection. Blockwise yank performs one cap lookup
before constructing row ranges and sends one batched decode request. There is
no request splitting or local FIX parsing.

Registers                                            *venue-reader-registers*

Without an explicit register, yank writes register 0, makes it unnamed, and
mirrors to + for clipboard=unnamedplus and * for clipboard=unnamed (both when
configured). Explicit command/Lua registers write only that destination.
Uppercase named registers append natively and leave register 0 unchanged.
Read-only/search/expression destinations are rejected; _ discards the operation.
Paste normally with p/P, including into a new buffer.

Mappings capture v:register. Unnamed or the clipboard-implied default (+ for
unnamedplus, otherwise * for unnamed) follows the default policy above.
Neovim cannot distinguish that default from an explicit mapping register prefix.
For an exact clipboard-only write, use :VenueReader yank + or:
>lua
    require("venue-reader").yank({ register = "+" })
<
Other mapping register prefixes remain explicit.

Late results after edits, rename, detach, configuration changes, changed internal
target registers or a newer yank are discarded. An external clipboard change
alone does not cancel the requested write. Errors, malformed answers and all-empty
results leave registers unchanged before commit. Native clipboard writes can
partially succeed on provider failure; some providers only emit warnings. The
adapter does not claim atomic clipboard updates.

==============================================================================
Mappings                                              *venue-reader-mappings*

No user keys are bound by default. Available targets:

<Plug>(VenueReaderYank)         Normal g@ operator or live Visual decoded yank.
<Plug>(VenueReaderTag)          Numeric tag (Visual/operator-pending).
<Plug>(VenueReaderValue)        Field value.
<Plug>(VenueReaderField)        Complete tag=value field.
<Plug>(VenueReaderMessage)      Complete message.
<Plug>(VenueReaderComment)      Comment.

For example: >lua
    vim.keymap.set({ "n", "x" }, "<leader>y", "<Plug>(VenueReaderYank)")
    vim.keymap.set({ "x", "o" }, "if", "<Plug>(VenueReaderField)")
    vim.keymap.set({ "x", "o" }, "iv", "<Plug>(VenueReaderValue)")
<
Syntax selections need nvim-treesitter-textobjects main. Its selection-mode,
lookahead and whitespace settings apply. The adapter's enabled predicate and
buffer opt-out guard selection. See |venue-reader-textobjects| and
|venue-reader-navigation| for setup and full field/message/comment motions.
